# AI 羊毛牧场权益估值与存量字段补全方案 V1

状态：业务原则已确认；美元估值与网站图表部分于 2026-10-10 实施，存量待研判项目继续处理。原则确认日期：2026-10-09（America/New_York）。

本方案统一已录入活动的美元估值、比较周期和字段缺口处理。以官方购买参考价值为优先依据，以领取后首 30 天为比较窗口；没有可直接折算的固定权益时，使用公开的标准创作者用量估算。无法可靠估值的权益允许形成明确结论，不强填数字。

本文件保留 V1 设计与适用边界。现役行为以[数据合同](../data-contract.md)、[通用规则](../../pipeline/learned-rules.md)和实际实现为准。本次已上架美元重估见[逐条报告](../valuation-audit-2026-10-10.md)；[管理员研判清单](../valuation-judgment-2026-10-10.md)中的项目仍待决定，不能仅凭方案认定这些项目已有可写入金额。

## 目标与范围

- 维持现有收录范围。普通付费套餐自带的不限量功能，不因能够估值就变成可收录活动。
- 处理所有已录入记录的字段缺口，同时检查已有美元数值、发放周期和重复计价问题，不只填空值。
- 美元代表权益的官方购买参考价值或明确标注的场景参考成本，不代表现金、实际到账金额或用户已经节省的费用。
- 补字段、平台准入和活动批准分别处理。保持原有审批状态，不自动上架、拒绝或撤下。
- 不能以推测填满字段来实现待办清零。暂未查明、来源不可访问及证据冲突必须保留真实状态。

## 价值定义与比较窗口

每条活动保留原始权益和完整权益信息，再生成首 30 天比较金额。

| 概念 | 定义 |
|---|---|
| 原始权益 | 官方实际赠送的余额、积分、Token、次数、时长、会员或席位 |
| 完整权益价值 | 有可靠依据时，对整个明确权益范围的购买参考价值 |
| 首 30 天参考价值 | 领取或激活后首 30 天内可获得或享有的权益参考价值 |
| 官方口径 | 官方面额，以及有对应官方购买依据的权益折算 |
| 用量估算 | 按标准场景和适用价格计算的参考成本，必须标明假设 |

官方口径优先。只有无法直接定价的权益才以场景估值作为主要比较金额；用户选择查看场景估值时，固定额度活动也必须受同一标准用量约束，不能把整包面额冒充该场景实际覆盖成本。

首 30 天表示领取初期的机会价值，不表示每个活动都会每月继续发放。一次性 $100 不随意除以 12，也不能写成每月 $100。长期权益的持续优势通过完整时长和刷新周期展示。

以下时间分别保存：领取窗口、个人激活后的使用有效期、额度刷新周期、估值覆盖期、价格适用时间。只剩一天能领取不代表只能使用一天；官方未公布截止不代表永久有效。

## 各类权益计算规则

以下金额均为解释规则的假设示例，不是当前产品报价。

| 权益情况 | 首 30 天处理 |
|---|---|
| 一次性赠送 $100，可立即使用 | 记 $100，标一次性并保留余额有效期 |
| 每月赠送 $10 | 记 $10，标明刷新周期，不承诺永久持续 |
| 固定积分、Token、次数 | 按适用的官方价格折算，保留单位与限制 |
| 赠送一年会员，官方月价 $20 | 前 30 天参考值 $20，另保留一年权益及对应完整购买价格依据 |
| 无限量且明确覆盖至少 30 天 | 标准 30 天用量乘对应价格，并受实际限制约束 |
| 无限量仅覆盖 7 天 | 标准用量按 7/30 缩放后计价，再检查配额及限流 |
| 无限量且截止未公布 | 展示假设可持续使用 30 天的条件估值，不当成官方保证 |
| 额外额度重置 | 只计新增可用权益，不能用整个会员售价直接代替重置价值 |
| 符合收录条件的身份专享折扣 | 计算对应期间节省的费用，明确实际需要支付的金额 |
| 申请制资助 | 区分确定额度与最高可申请额，独立排行 |

短期固定赠金仍按面额记录，不因只有 7 天有效就把 $100 乘以 7/30。持续使用型权益的标准用量才随覆盖时长缩放。余额分期释放时，只按首 30 天可获得的部分计入该窗口。

会员按会员权益本身估值，不再叠加包含的每个模型。只有有可核实的对应购买方案时才能计算完整会员价值；不能把一年权益的完整价值与首月比较值混用。

## 标准创作者用量 V1

这些数量是本项目确认的比较约定，不是调查得到的用户平均用量，也不是对创作者需求上限的判断。估值须记录使用的基准版本。

| 场景 | 每 30 天标准用量 |
|---|---:|
| 文本对话 | 输入 1,000,000 Token 加输出 200,000 Token |
| 编程助手 | 输入 10,000,000 Token 加输出 1,000,000 Token |
| 图像生成 | 100 张 |
| 视频生成 | 600 秒生成素材，即 10 分钟 |
| 语音转文字 | 1,200 分钟音频，即 20 小时 |
| 文字转语音 | 10,000 字符 |

图像固定尺寸和质量，视频固定分辨率与模式，语音固定计费档位。不同规格不直接混算。具体规格模板是实施前需要补齐的配置，不能在未指定规格时伪称所有模型可比。

视频按实际生成素材时长计，包括未采用的素材。例如生成三段各 10 秒、仅采用其中一段，生成量仍为 30 秒，不按最终成片 10 秒计。

基本计算顺序：

1. 选择适合活动主要用途的场景及规格。
2. 按实际权益覆盖期限制首 30 天标准用量；未知持续时间须显示假设。
3. 在总额度、每日额度、共享配额和其他已知限制内计算能覆盖的用量。
4. 将能覆盖的用量按匹配价格计价。

文本类公式为输入 Token 数乘输入单价，加输出 Token 数乘输出单价，先统一价格单位。不能继续将所有 Token 一律按输入价处理。

例如输入价 $2/百万 Token、输出价 $10/百万 Token，文本对话完整 30 天标准成本为 `1 × 2 + 0.2 × 10 = $4`；仅免费 7 天且没有其他限制时约为 `$0.93`。

共享预算或多个限制存在关联时，不能将各部分独立取上限后相加。最大上下文不等于每次实际用量，速率上限乘整月时间不等于典型用量。只有请求次数且无法确定对应消耗时，不擅自补造每次 Token 数。

## 多模型默认选择

固定美元余额、可直接折价的积分和赠送完整会员优先按权益本身定价，不因包含模型多而累加价值。

确实需要场景估值的多模型活动，采用同场景成本中位模型作为默认基准：

1. 枚举实际免费可用的模型，排除仅在导航出现或需要额外付费的模型。
2. 去除同模型别名、重复入口，处理历史快照及版本重复，避免同一模型的大量变体影响中位数。
3. 筛选能够完成同一场景、同一输出规格的模型；文本对话与编程分别计算。
4. 使用相同标准用量计算各模型参考成本，按成本从低到高排序。
5. 奇数个候选取中间模型；偶数个取中间两个中成本较低者。
6. 展示默认模型、价格和公式，允许用户切换模型查看其他使用方案。

例如同一场景五个模型成本为 $4、$8、$12、$30、$80，默认选择 $12 对应的模型，不相加为 $134。这里的中位是购买成本中位，不表示质量中位，也不表示用户真实选择占比。

| 额度关系 | 处理 |
|---|---|
| 多模型共享一个额度池 | 额度只计一次，一份工作量按选定使用方案分配 |
| 多模型均不限量 | 默认同一场景选一个基准模型，不将完整工作量在所有模型各算一次 |
| 每模型独立赠额 | 完整权益可分别核算；场景估值仍受标准总工作量约束 |
| 图片或视频二选一 | 分别展示使用方案，不能把两种产物上限相加 |
| 综合产品含多个模态 | 默认采用主要用途，不自动叠加所有场景 |

缺价格模型不按零处理，不进入成本中位数。展示已计价模型数与实际可用模型数，部分缺价或覆盖不足时估值标为暂定。完整模型清单和中位数候选集分别保留，以便复算筛选过程。

## 价格来源和适用边界

价格查找顺序为：

1. 本平台相同权益的官方售价或加购价。
2. 同模型、同版本、同规格的原厂官方价格。
3. OpenRouter 中匹配模型版本与服务规格的实际付费价格。
4. 均无可靠价格时，记录无法折算或公测未定价，不拿其他模型顶替。

本平台有官方加购价时优先使用；没有加购价、需要按积分套餐折算时，沿用同平台各适用套餐中最低单位费率的保守原则，并保存套餐价格、所含积分与适用条件。

适用费率必须先证明单位相同。不同套餐即使都叫 credit，也可能对应不同美元面值、模型消耗或 API/网页费率；同一个账户使用统一账本不能证明跨套餐等值。缺少赠额所属套餐的兑换率或同规格资源对应关系时，金额留空，不套用其他档位的最低单价。

纯请求次数限制可以估算固定标准用量，但须核实免费通道的具体模型、单次上下文/输出限制及速率，证明标准月用量可合法安排在配额内。例如 1,000 次各输入 1,000、输出 200 Token 可以覆盖文本标准量；这只是可行性安排，不是实际平均消耗或官方赠送 Token 数。不能用请求数乘最大上下文估出理论赠额。免费运行时间也不自动包含模型费用，须确认计费范围。

原厂和 OpenRouter 价格仅为匹配模型用量提供成本参照，不能据此估出整个编程工具、工作流或会员价值。即使单价来自官方，乘上标准用量后的金额仍是用量估算。

保存价格来源 URL、来源类型、模型标识及版本、币种、计费单位、输入输出或其他价格维度、适用条件、核价日期及适用时间。缓存、批处理、路由或质量档位有区别时必须匹配，不能取不适用的最低价格。

价格来源可以补充估值依据，不能替代活动发放方证据或改变证据级别。OpenRouter 价格也不扩大平台准入或活动收录范围。

## 公测未定价

| 情况 | 处理 |
|---|---|
| 公测免费，但已公布适用的正式售价 | 用已公布售价计算标准用量成本，注明价格适用时间 |
| 原厂未定价，OpenRouter 有同版本同规格实际付费价格 | 可按该价格估算并标明来源 |
| 本平台、原厂、OpenRouter 均无可靠付费价格 | 结案为公测未定价，美元留空 |

公测期间的 $0 不能自动理解为正式购买价值，也不能用其他免费路由的 $0 证明活动没有价值。新版本不能自动继承上一代价格，能力接近也不代表售价接近。

公测未定价的活动显示“公测免费 · 价值待定”，关闭对应美元催补提醒，不作为 $0，不进入美元排行或金额合计。混合活动可按有价模型计算暂定值，并显示计价覆盖情况；全部模型均无价时不产生数字。

允许补充“参考模型同等用量成本”，但只能说明参考模型的成本，不写入该公测模型估值，不进入其排名或统计。后续出现可靠售价时重新估值。

## 领取对象与不确定额度

- 默认按单个符合条件的领取者估值，不将所有人或所有档位的权益相加。
- 会员档位的重置奖励分别列值，默认比较不得采用最高档冒充所有人可得。
- 邀请双方奖励分别归属，不能自动算给同一个人。
- 团队席位注明人数和团队上限，不当作个人价值。
- 申请制单独排行。“最高可申请”不是保底可得；没有保底时不生成下限。
- 模型选择导致的场景成本范围，不是活动保证赠送范围；不能继续把它与档位范围、申请上限统一塞入同一对下限上限字段而不区分语义。

## 展示与统计

卡片优先显示官方权益价值，并明确“一次性”“每月”或“前 30 天”。用量估算加“约”及方法标签；未知期限的条件估值须显示持续时间假设。

允许官方口径与用量估算共同排序，但保留方法差异，提供“仅看官方价值”筛选。这是一种实用比较，不表示面额和场景成本具有相同确定性。

首页、平台页和其他汇总分别展示“官方口径合计”与“用量估算合计”，不合成一个无说明的总金额。只在同一比较窗口内汇总，且每个活动按选定方法计一次，不能同时加入其官方值和场景值。申请制保持独立。

展示已估值覆盖情况。无法估值不当成 $0，不在价值评分中自动按最低价值处理；具体评分兼容方式在实现时单独验证。“我的”中的参考值不得称为用户已经节省的金额。

公开估值方法、价格来源及必要假设放在专门的估值说明区域。`title`、`valueText`、`steps`、`creditValidity` 继续面向领取者描述权益和条件；核验过程、旧值纠错、审批待办放在内部 `reviewMemo` 或审核记录，不混入公开简介和 `adminNote`。

## 字段缺口结案

结案按字段进行，同一条活动可以有已完成项和仍待解决项。

| 结果 | 含义与后续 |
|---|---|
| 已补齐 | 保存事实和依据，关闭对应提醒 |
| 已确认未公布 | 经核查确认官方没有公布该信息，保存结论，关闭本轮补字段提醒 |
| 不适用 | 字段对该权益不适用，保存原因并关闭提醒 |
| 已核实但无法折算 | 保留原始权益及依据，不反复催补美元 |
| 公测未定价 | 价值待定，待可靠价格出现后重新估值 |
| 暂未查到 | 保留待核查，不等同于官方未公布 |
| 来源不可访问 | 保留访问故障和重试状态，不自动判定活动失效 |
| 证据冲突 | 保存冲突，等待裁定 |

关闭美元提醒不绕过资格、证据等阻断。已结束但缺实际开始日期等影响历史计算的问题，不能靠标记未公布就伪造有效日期或放行错误统计。

新证据或相关条款变化可以重新打开对应缺口。不能因模型重复抽取或同一未知状态反复制造待办。管理员亲测证据仍只能由管理员明确确认。

## 建议的数据表达与实施改动

下列是逻辑数据需求，不是已经落地的数据库字段名。实现时确定具体 schema 和兼容方案，不直接重新解释现有 `usdEstimate` 与 `usdMax` 的全部旧值。

| 数据组 | 必须承载的信息 |
|---|---|
| 权益事实 | 原单位、数量、发放周期、使用有效期、领取窗口、共享范围、对象与席位 |
| 估值结果 | 完整权益值、首 30 天值、金额语义、方法、状态、是否暂定 |
| 场景配置 | 标准用量版本、场景、质量规格、覆盖时长与假设 |
| 模型选择 | 完整可用清单、去重分组、合格候选、基准模型、计价覆盖数 |
| 价格证据 | 来源、版本、单位、价格维度、币种、日期及适用条件 |
| 计算记录 | 公式、限制、实际采用的输入、中间结果与舍入结果 |
| 字段结案 | 字段、结论、依据、核查时间、重新打开的原因 |
| 修订保护 | 原值、新值、修改依据、规则版本及审批状态 |

抽取、后台检查、审核、前端和统计应复用同一套计算与状态规则，避免每个页面自行解释金额。历史修订需能复算，不能在价格更新后无痕改写历史参考值。

实施前需明确的配置细节包括：图像视频质量模板、模型版本归组规则、候选成本相同的稳定选择规则、非美元汇率来源与日期、计价覆盖不足的提示策略、核价刷新频率，以及旧评分和旧 API 的兼容方式。这些不属于本次已确认的具体参数，不能冒充已获确认的业务数值。

## 存量处理和发布步骤

1. 固化数据合同、共享计算规则和结案机制，同步通用规则、仓库审核技能、抽取及前端约定。
2. 重新读取全量已录入记录、提案和受阻线索，分别盘点字段缺口及旧金额问题。未形成条目的受阻线索不能靠补金额关闭。
3. 输出逐条差异清单，包含旧值、拟定新值、公式、证据、处理状态和未解决问题。
4. 先处理面额或价格明确的记录，再处理会员、多模型、无限量，最后处理冲突、不可折算及公测未定价。
5. 按已批准字段与人工修订保护规则实施迁移，保存修订依据，保持审批状态；不能借估值迁移触发批量批准。
6. 修正卡片、排序、首页、平台累计、申请制和个人进度，按实际改动完成测试与构建。
7. 按实施任务授权提交、推送、部署，并分别核实数据库读回、页面展示和统计。文档写入本身不代表这些步骤已授权或已执行。

新旧金额语义应配套切换，避免后端已写入新值而前端仍按旧含义计算。迁移前保留可恢复的旧值和配置，具体发布、备份与回滚过程遵循[运维说明](../operations.md)。

## 验收标准

| 验收案例 | 预期结果 |
|---|---|
| 一次性 $100，7 天有效 | 官方参考值 $100，标一次性及有效期，不乘 7/30 |
| 每月 $10，无全局截止 | 前 30 天 $10，不生成永久总值 |
| 一年会员，月价 $20 | 首 30 天 $20，完整权益单独保存，不叠加所含模型 |
| 文本无限量，仅 7 天，完整月场景成本 $4 | 约 $0.93，标用量估算及覆盖时长 |
| 共享 $5，可用许多模型 | 官方价值 $5，不按模型数量相乘 |
| 五模型同场景成本 $4、$8、$12、$30、$80 | 默认基准为 $12 对应模型 |
| 四模型同场景成本 $4、$8、$12、$30 | 默认基准为 $8 对应模型 |
| 一个模型多个别名和重复入口 | 不增加中位数权重 |
| 图片或视频共用积分 | 不累加两类产物最大价值 |
| 请求上限已知但 Token 消耗未知 | 不用最大上下文补造用量 |
| 部分模型公测无价 | 不以零参与中位数，显示覆盖情况及暂定标识 |
| 全部模型公测无价 | 美元为空，字段可结案，不进美元排名合计 |
| 最高可申请 $100,000，没有保底 | 只标申请上限，不生成保底下限，独立排行 |
| 官方未公布日期与页面访问失败 | 前者可按证据结案，后者保持待核查 |
| 修改估值或字段结案 | 审批状态不变，原有证据阻断仍有效 |
| 官方值与场景值并存 | 同一活动不重复进入合计，两个口径分别汇总 |

所有纳入处理范围的记录都有明确结果；仍需查证的项目单独列出。每个数字能追溯到权益、模型、用量、价格和公式，未知值不冒充零，共享权益不重复计价，周期不混用。

代码实现时至少执行 `npm run typecheck`、`npm test`；前端改动加 `npm run build:web`，并验证上述业务边界。通过测试、完成部署和生产读回分别留证，不能互相替代。
