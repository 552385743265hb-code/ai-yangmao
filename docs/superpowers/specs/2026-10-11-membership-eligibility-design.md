# 会员资格选择式录入与匹配设计

日期：2026-10-11。状态：用户已确认并授权直接实施；代码与迁移已完成，发布核验见运维凭证。

管理员日常审核通过选择产品、套餐和条件录入会员资格，不必手写自然语言。用户在“我的条件”选择实际拥有的会员，系统按固定标识和资格逻辑匹配。套餐正式名称、文案改写和价格变化不产生新的会员身份。

## 目标与边界

本次解决后台手工录入、采集候选、条目门槛展示和个人筛选之间的一致性。保留现有非会员门槛；本次不重判福利收录范围、价格或资格事实，不自动批准待审或恢复已拒记录。

用户已确认标准会员目录、结构化资格和识别预览的方向，并提出去掉手工自然语言环节。本设计采用选择式审核；自动采集和旧数据迁移仍可产生待确认的识别结果，管理员用选择控件纠正它们。

## 方案选择

| 方案 | 结果与取舍 |
| --- | --- |
| 只检查是否含平台名 | 改动小，但无法可靠表达“或”“且”“排除”，同义文字仍产生不同会员 |
| 自然语言输入后自动改写 | 输入灵活，但管理员仍须检查模型是否改错资格，不能作为唯一保存依据 |
| 标准目录与选择式资格编辑 | 本次采用；常规审核无需编写会员句子，服务端可以确定性校验和匹配 |

## 已核实的现状

- `web/src/app.js` 从所有 `member:` 字符串提取“我已有的会员”，并用整串文字相等判断匹配。同一套餐换表述即成为另一项。
- 后台 `reqMember` 是单行输入框。读取时只取第一项 `member:`，保存时只生成一个会员字符串，可能丢失多项会员条件。
- `src/shared/ingest.ts` 只校验 `member:` 后存在文字，无法校验产品、套餐、或且关系及排除项。
- `src/shared/identity/types.ts` 的 `terms-v1` 资格仍包含文字数组；修改会员结构需要兼顾权益身份、提案、去重、历史决定和旧客户端。
- 浏览器将用户条件存在 `ym-cond`。不能把旧的裸 `Pro` 选择自动扩成多个平台的 Pro。

这些问题需在录入和存储处解决，不能只替换页面标签。

## 管理员编辑体验

勾选“需要会员”后显示资格编辑器。默认只有一组，组内选项全部满足；新增“或另一组”可表达替代资格。每个资格项均使用搜索选择控件。

| 控件 | 选择与行为 |
| --- | --- |
| 会员产品 | 从已核实目录选择，例如 Claude、Cursor；不能由条目平台自动锁定，因为活动可接受其他平台会员 |
| 合资格范围 | 指定套餐、任一付费订阅、任一订阅；后两者仅在原文明确支持该范围时选择 |
| 套餐 | 指定套餐时多选，每个套餐显示产品全称；同一资格项中的套餐满足任一个即可 |
| 排除套餐 | 从同一产品已核实套餐中多选；只限制本项能用于满足条件的套餐 |
| 补充限制 | 订阅日期、月付或年付、席位类型、地区、旧版套餐等按类型显示日期/枚举/数字控件 |
| 条件关系 | 组内“全部满足”；各组“满足任意一组”。界面提供“并且一项”和“或另一组”，显示实时白话预览 |

正常审核不显示必填的会员自然语言框。名称、条件句和前台标签由选择结果生成。证据原文仍单独保存，核验记录沿用内部备注，不参与自动匹配。

补充限制尚不能表达时可保存为“待核实”草稿，不能悄悄丢掉限制再通过；也不能把自由备注当成机器已理解的条件。没有修改会员门槛的其他字段编辑不强制管理员重填旧会员资格。

### 用户给定例子的操作

“除了免费档以外的 SuperGrok 订阅，或 Cursor 订阅”在界面上表示两个替代组：

```text
满足以下任意一组
  第一组：选择 SuperGrok 对应的已核实产品与订阅范围
          按目录和证据确认排除的档位
  或
  第二组：选择 Cursor 与已核实的订阅范围
```

这只是录入示例，不证明存在名为“免费档”的 SuperGrok 套餐。目录或证据未能对应时显示待核实；不能把“免费档”自动改成 SuperGrok Lite，也不能把“Cursor 订阅”自动改为 Cursor Pro。“任一付费订阅”已排除确定的免费档时，不重复生成无意义排除条件；试用、赠送会员是否符合仍按具体资格，不按用户是否付过钱猜测。

排除条件作用于资格项。例如第一组排除了某 Grok 套餐，而用户还有符合第二组的 Cursor 订阅，整条仍满足；持有被排除套餐不构成全局取消资格。

## 标准会员目录

目录区分厂商、会员产品和具体套餐。使用固定、不依赖展示名的 `productId`、`planId`；产品可关联平台但不得强制一一对应。Go、Zen、Claude、Claude API 等不同产品或通道不得按同一公司自动合并。

每个产品及套餐保存正式名称、别名、证据链接、核验日期、状态与目录修订号。套餐的付费/免费属性允许未知；月付、年付、地区与席位差异按证据建属性或独立变体，不凭名称推断。曾经存在的旧套餐可停用但仍供历史条目显示。

- 别名只有在同一产品上下文内且唯一时自动对应；`Pro` 不能是全局别名。
- 名称改写保留 ID；权益不同的新档位不能通过改名冒充旧档位。
- 不建立通用“Pro 高于 Plus”的等级假设；“某档及以上”必须选择经证据确认的套餐集合。
- “任一付费订阅”仅匹配该产品已核实为付费且状态适用的套餐，未知档位返回待确认；新增目录项需展示会受影响的广泛范围条目，再确认生效。
- 价格是套餐/资格的说明属性，不作为身份键。同一会员不同活动的价格、赠额、有效期不能各生成会员选项。

目录缺项时在编辑器中点击“新增会员产品/套餐”，在独立小窗填写正式名称、所属产品和来源，查重后保存待核实目录项。该步骤不可完全取消文字输入，但它是目录维护，不是每次审核都手写资格句。未核实目录项可以挂到草稿，不能用于已确认匹配或首次发布。

## 存储与服务端合同

在条目与候选中新增版本化 `membershipRequirement`，包含条件结构、确认状态、原文证据引用和修订号；产品/套餐是稳定 ID 引用。`requirements` 中的非会员项继续沿用现合同。旧 `member:` 文案作为兼容投影由新结构生成，不能再独立编辑或与结构冲突。

结构采用受限的两层逻辑：`anyOf` 表示替代组，每组 `allOf` 表示同时满足的资格项。资格项包含产品、范围、套餐/排除套餐集合及类型化限制；每组、每项数量设有限上限，避免无限嵌套。无需会员使用明确的 `not_required`，与未知/待核实区分；空组或全部套餐均被排除一律非法。

前后端共用校验、文案生成和匹配模块。服务端要求所有 ID 存在、套餐归属正确、目录状态适用、范围与套餐选择不矛盾、日期限制有效，并保存管理员确认的结构与来源。前端提示之外，编辑API、采集入库、管理CLI和审批入口均使用同一校验。

保存和批准继续带当前审核版本及目录修订检查；并发变化返回冲突，不能自动刷新版本后重放。保存草稿不等于批准；目录审核和福利审核各自独立。

### 权益身份与历史兼容

会员资格结构属于真实资格事实，不能只附加前端字段而让去重继续忽略它。正式实施引入 `terms-v2` 的版本化会员资格表达，并同步共享schema、规范化、比较器、入库、数据库约束和身份服务。

既有 `terms-v1` 历史事实、哈希、批准/拒绝决定保持不可变。新增 V2 基线和明确的旧版映射关系；迁移仅对证据支持、资格等价的条目建立映射，保留原批准/拒绝状态，不制造新活动、重审事件或通知。新旧版本比较必须先经过等价转换；无法解释的旧文字返回待核实，不能因哈希不同自动作为新权益。

同一组内顺序、别名及显示名称变化不构成条款改变；改“或”为“且”、修改排除项、订阅日期或适用套餐集合属于资格变化，进入原条目的正常更新审核。针对未知资格先进入补核流程，不能放宽成人人可领。

## 用户端选择与判断

“我已有的会员”按产品分组，只展示标准套餐，不展示某个活动的整段资格句。同一个套餐在多条活动出现时只选一次。用户可添加多份订阅，并按需填写地区、计费周期、开始日期和席位类型；只在这些信息影响所看活动时提示补充。

判断采用“满足／不满足／还需确认”三种结果：

- 单项指定套餐：持有至少一份符合产品、套餐及限制的订阅即可；排除项只淘汰不合资格的那份订阅。
- 组内全部满足：任一项明确不满足则不满足；其余有未知则待确认。
- 组间任一满足：任一组满足则满足；全部不满足才不满足，否则待确认。
- “只看我能薅的”只纳入确定满足，待确认单独提示补资料，不能当满足或永久不满足。

展示标准名称不改变用户实际持有的会员。旧本地选择一对一、无歧义对应时自动迁移；裸Pro、整段多平台条件或组合句要求重新选择，并保留未解决旧值供用户核对。不得将旧组合句解释成用户同时持有全部会员。非会员条件、想领和已领记录保留。

## 自动采集与旧数据迁移

采集器可以从官方自然语言提出产品、套餐及资格结构，但不能创建已核实目录项或自行通过。匹配不唯一、来源未说明资格、出现未知限制时进入待核实。审核界面显示结构化选择及原文对照，管理员无需重写句子。

迁移前导出当前条目、已批准版本、待审候选及目录版本备份；逐条生成旧值到结构的映射。先处理唯一明确的名称，复杂“以上／旧用户／排除／组合资格”单列复核。上一轮补全全称不证明复杂资格已经解释正确，不能全部无条件自动迁移。

迁移分别覆盖公开基线和候选，保留两者原有差异、手工字段、证据、批准/拒绝状态及关联ID。历史修订和拒绝原文原样保留。线上切换前确保所有正在公开的会员门槛均已有确认结构，未完成则保留旧版展示并将其新匹配结果标为待确认，不让记录消失。

旧接口可以读取生成的会员文案；旧写入只能作为待确认输入，不能静默覆盖确认过的结构。版本化API响应与浏览器存储，并使用现有公开缓存generation机制刷新；回滚恢复旧兼容读取，冻结无法识别新结构的写入，保留所有新结构和审核记录。

## 验收标准

1. 手动审核无需输入会员句子即可完成普通、多个备选、同时满足和排除资格；新增目录项有单独入口。
2. Claude Pro与Cursor Pro不混淆；别名或改名保留相同套餐身份；目录缺项无法悄悄新建已核实会员。
3. “Grok合资格订阅或Cursor合资格订阅”持有任一即可；同时持有被排除的Grok档位与合资格Cursor订阅仍满足。
4. “A且B”仅持有A时不满足；未知日期/试用资格返回待确认；空组、跨产品排除和全排除服务端拒绝。
5. 保存再次打开不丢失多个会员条件；后台、API、采集、CLI、批准和身份去重使用一致结构及规则。
6. 套餐顺序或展示名修改不触发新活动；真实资格变更按版本锁进入更新审核；并发编辑不会覆盖新修改。
7. 迁移保留公开与待审差异、原审批状态、证据、关联ID和非会员字段；旧含糊本地选择要求重选，不扩成多个会员。
8. 真实浏览器验证录入、保存、读回、个人套餐选择和“只看我能薅的”完整流程；测试包括失败与未知路径。
9. 完成typecheck、测试、前端构建和兼容回滚演练；部署后以线上接口与UI证明生效，不能仅凭构建或推送结果宣称上线。
