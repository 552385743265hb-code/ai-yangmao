# 后台审核流程与卡片整理（2026-10-11）

本次按用户要求保留原来的完整待审卡片，调整队列和自动补证衔接，不自动批准上架。

## 用户操作

- 顶部统一显示活动待审、线索复核、暂停发布数量；活动数量来自完整服务器队列，不以身份接口第一页的 5 项代替总数。
- 线索复核：尚未形成活动，默认折叠，继续按原计划自动搜索/核验。
- 活动待审：沿用权益摘要、条件、来源原文、建议、检查项和编辑/批准/拒绝卡片。分成“等待你决定”和“系统补证 / 补证受阻”。普通活动不再以满屏未知事实表作为主界面。
- 暂停发布：独立折叠，明确不计入待审、无需日常处理；明确重开后仍需重新审核。
- 身份冲突仍有独立处理卡，技术事实折叠；已在完整卡片呈现的任务不会在身份接口翻页后重复出现。
- 身份托管活动编辑后只保存草稿，重新展示最新内容和审核版本；不会把保存成功说成已经上架。保存心得不丢失任务版本。

## 系统补证边界

媒体转述、缺少核心权益原文、没有资格/领取依据或被标记证据缺失的活动进入现有官方复核队列。仅有“compose_video：限时免费”等功能标签不算充分材料。未知日期和金额继续保持未知，不为了完成补证制造数据。

对历史迁入、尚无结构化身份事实的新活动，补证只暂存待审版本。要求有效官方任务、实际发放方、对应活动类型、可信且未截断的抓取凭证、正文哈希以及逐段可定位的原文；管理员亲测不能由模型设置。保存前再次校验任务、实体、原活动及官方任务版本，人工编辑发生后旧结果不能覆盖。

原始活动与人工估值/修改保留。补证给出“建议通过 / 建议作为历史收录 / 需要人工核对”；这是建议，公开状态不变。最终人工批准仍验证发布条件与当前审核版本。人工核对图片中的资格或有效期不要求凭空补文字摘录，但自动补证必须保留其能证实的领取/资格依据。

现有搜索、重试、预算及定时运行沿用；本次不增加预算，不手动启动真实采集或发送消息。上架依然需要管理员明确操作。
