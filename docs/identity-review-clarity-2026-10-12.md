# 活动身份复核界面与补证验收

日期：2026-10-12。本文记录本次实现边界；线上版本和迁移台账以发布时的实测读回为准。

## 审核流程

后台的「权益活动查重」卡片展示候选权益的真实标题、额度、发放产品、来源和原文。「身份不明」不再代替候选标题。系统先逐条验证候选来源，逐页读取同一发放产品的历史活动；完成前不展示身份操作。来源不可信、产品未准入、候选与官方来源冲突、历史活动缺少可展示条目时保持人工待审，不自动通过。

可核对时，卡片展示具体旧活动和系统建议。历史活动超过 200 项时，审核者还需在卡片中逐页加载完整列表，才能选择旧活动或建立独立的待审活动。同一官方页面只作为优先核对线索，不能证明同一权益。模型辅助结果是建议，不产生自动通过、合并或拒绝；此前的模型建议保留在任务记录中。

系统补证只使用已登记且经官方来源规则核实的页面；重新取得的直接来源与候选原文摘录必须对应。新观察记录接到候选的决策证据，旧观察记录保留，任务记录保存原观察 ID 与新观察 ID。多个来源分别核对，单个来源的通过标记不扩散到其他来源。当前可读的系统建议仍不能替代管理员核实领取机制、独立活动轮次和拒绝历史。

若自动补充资格或领取方式原文多次受阻，但待审活动已有足够的官方权益原文，系统将其移回「等待你决定」，明确说明缺口；人工通过时仍由服务端检查平台准入、官方来源、核心权益证据和重复活动。真正缺少核心权益原文或标记为 `evidence_missing` 的活动继续待补证。成功通过后，旧补证失败只显示为审批前历史记录，不再冒充当前阻断状态。

身份准备队列优先处理 72 小时内截止、7 天内截止和标题明确标为限时的活动，每轮仍为最老待处理任务保留一个名额。临期来源补证失败后按 30–60 分钟退避，普通任务保持 6 小时；不新增模型预算或自动批准。卡片显示截止信息与最早可重试时间，实际执行仍取决于下一轮定时任务。已有核实来源的限时任务允许审核员点击「立即核对历史活动」，每次最多读取四页；这只推进查重，来源缺失仍需补证，身份决定和发布都必须单独人工确认。日期未知的限时文字只是排序线索，不能凭标题推断截止日；已过期日期不抢占临期队列。

## 验证与限制

- 回归覆盖：真实候选展示、历史分页、超过 200 项的列表门槛、来源逐条补证、旧模型建议保留、canary 排除、人工决定后的待审状态、并发/重放、错误来源和前端卡片交互。
- 本地事务验证使用合成数据、完整迁移和 Wrangler D1，检查语句预算、外键、旧观察保留以及无自动业务决定。
- 发布前重新运行 `npm run typecheck`、完整 `npm test`、`npm run build:web`、本地 Wrangler D1 验证，并检查当前主分支和目标生产迁移台账。本次没有新增数据库迁移。
- 官方网页不可访问、正文不足或摘录不匹配时维持待审及补证退避。系统不会凭标题、金额或模型相似度自动上架。
